# בריף עיצוב: הבעל אירוע מסמן ומעלה, וזה נשמר בדיסק

המסמך מסביר את העמוד `/admin/e/<אירוע>/design`, מה הוא שומר בדיסק, ואיך מחברים אליו אוטומציה (בדרך כלל Claude עם Figma ו-Canva) שלוקחת משם ומייצרת את העיצובים.

## הרעיון

העמוד לא מייצר עיצוב. הוא אוסף **בריף**: מה צריך להיות כתוב, איך זה צריך להרגיש, אילו תמונות יש, ולכל פריט (מסכי האפליקציה, מסגרת למגנט, סטיקרים, מסגרת לפוסטר, שלט, הזמנה) באיזה גודל הוא, מה הבעל אירוע אומר עליו, ואיפה יושבים הכותרת, התאריך, המקום, שם האורח, הלוגו וקוד ה-QR. הכול נשמר כקבצים מסודרים בתיקייה של האירוע. כל מי שיודע לקרוא קבצים (Claude, סקריפט, מעצב) לוקח משם ומייצר. כך האפליקציה לא צריכה חיבור ל-Figma או ל-Canva, שדורש הרשאות נפרדות לכל מארגן.

## איך משתמשים

מי שיש לו הרשאת ניהול באירוע (בעל הפלטפורמה או מנהל האירוע) נכנס מהדשבורד ל"📐 בריף עיצוב", ויש בעמוד:

1. **פרטי האירוע כפי שיודפסו**: כותרת, תאריך, מקום ושפה. אלה הטקסטים המדויקים שיופיעו על הפריטים, לכן כדאי לכתוב אותם כמו שרוצים לראות אותם (למשל התאריך העברי).
2. **אווירה**: אופי, מה אוהבים, ממה להימנע.
3. **תמונות**: הזמנה, לוגו, השראה, או פריט קיים שצריך להתאים אליו. עד 40 תמונות. לוגו עם רקע שקוף נשאר שקוף.
4. **פריטים ליצירה**: מוסיפים לפי סוג, ולכל פריט בוחרים גודל (מסך טלפון, מגנט 5×7.5, גלויה 10×15, שלט A5 או A4, סטיקר ועוד), כותבים במילים מה רוצים, מסמנים תמונות להסתכל עליהן, וגוררים כל רכיב למקומו על מסגרת בצורה ובצבעי העיצוב של האירוע. אפשר גם להזיז עם החצים במקלדת, לבחור גודל (קטן, בינוני, גדול) ויישור. עד 30 פריטים.
5. **שמירה**. פעולות העלאה ומחיקה של תמונה נשמרות מיד, שאר השינויים בלחיצה על "שמירה".

## מה נשמר בדיסק

`DATA_DIR/events/<אירוע>/design/`:

| קובץ | מה זה |
| --- | --- |
| `brief.json` | הבריף המובנה (הסכמה: `BriefSchema` ב-`src/lib/platform/design-brief.ts`) |
| `brief.md` | אותו תוכן במילים, עם כל גודל ומיקום כתובים במפורש. נכתב מחדש בכל שמירה |
| `assets/<מזהה>.png` או `.jpg` | התמונות שהועלו |

ערכת העיצוב עצמה נשארת במקומה, ב-`DATA_DIR/events/<אירוע>/theme.json`. כפתור "חבילת בריף (ZIP)" מוריד הכול יחד: `brief.json`, `brief.md`, `theme.json`, `tokens.json` (צבעים בפועל, גופנים, צורה ומשתני CSS) ו-`assets/`.

קטע מ-`brief.json`:

```json
{
  "event": { "title": "בר מצווה לדוד כרמל", "dateText": "כ״ה בחשוון תשפ״ז", "venueText": "אולם הכרמל, חיפה", "language": "he" },
  "branding": { "tone": "חגיגי, זהב על ירוק זית", "likes": "", "avoid": "" },
  "deliverables": [
    {
      "id": "df5dcc440", "kind": "magnet", "name": "מסגרת למגנט", "notes": "", "size": "magnet_5x7",
      "elements": {
        "title": { "x": 0.5, "y": 0.14, "size": "l", "align": "center" },
        "date":  { "x": 0.5, "y": 0.25, "size": "s", "align": "center" }
      },
      "references": ["a7154a4e3"]
    }
  ],
  "assets": [{ "id": "a7154a4e3", "role": "invitation", "name": "הזמנה", "ext": "png", "addedAt": "…" }]
}
```

### איך קוראים מיקום

- `x` ו-`y` הם מרכז הרכיב, כשבר בין 0 ל-1 של **הפריט המוגמר** (בלי השוליים לחיתוך), מהפינה השמאלית העליונה. 0.5 ו-0.5 הוא המרכז.
- גודל טקסט: קטן, בינוני וגדול הם 4, 7 ו-11 אחוזים מגובה הפריט. גודל לוגו ו-QR: 15, 25 ו-40 אחוזים מרוחב הפריט.
- `align` הוא יישור הטקסט בתוך התיבה. בעברית "start" הוא הצד הימני.
- בפריטי דפוס הקובץ הסופי כולל שוליים לחיתוך (bleed) מכל צד, והגדלים המדויקים (מ"מ, פיקסלים, dpi) כתובים ב-`brief.md`. הגדלים של מגנטים וגלויות באים מאותם פרופילי הדפוס של תור ההדפסה (`src/lib/print/profiles.ts`), כך שהבריף והדפוס תמיד מסכימים.

## לחבר אוטומציה

שלוש דרכים, מהפשוטה לאוטומטית:

1. **Claude על אותו שרת או על מחשב עם הקבצים.** מבקשים: "תיצור את העיצובים מהבריף של האירוע carmel". הסקיל `.claude/skills/event-theme-from-invitation` כולל מצב בריף: Claude קורא את `brief.md` ואת התמונות, לוקח את הצבעים מ-`tokens.json`, ויוצר כל פריט ב-Figma (מסכים) או ב-Canva (דפוס, סטיקרים) לפי הגדלים והמיקומים. הכפתור "העתקת הנחיה ל-Claude" בעמוד מעתיק הנחיה מוכנה.
2. **Claude בלי גישה לדיסק (למשל סשן בענן).** מורידים את חבילת ה-ZIP ומעלים אותה לשיחה, או נותנים לאוטומציה משתמש מסוג **צופה** באירוע. צופה מתחבר ב-`POST /api/auth/login` וקורא `GET /api/admin/e/<אירוע>/design/export`, כך שהיא לא יכולה לשנות כלום.
3. **הרצה מתוזמנת.** אפשר להגדיר ל-Claude שגרה (routine) שמריצה את ההנחיה מדרך 1 או 2 בכל פעם שהבריף משתנה. שימו לב: Figma ו-Canva כותבים לחשבונות של מי שחיבר אותם, וייתכן שיידרש אישור על כל כתיבה.

מה שאוטומציה לא צריכה לעשות: לכתוב לתיקיית `design/`. היא של הבעל אירוע, והאפליקציה כותבת מחדש את `brief.md` בכל שמירה. התוצרים נשמרים אצל Figma ו-Canva או בתיקייה אחרת.

## אבטחה

- קריאה ויצוא דורשים הרשאת צפייה באירוע. שמירה, העלאה ומחיקה דורשות ניהול, ובקשה מאתר זר נחסמת. כל שינוי נרשם ביומן הפעולות (`design.update`, `design.asset.add`, `design.asset.remove`, `design.export`).
- רשימת התמונות שייכת לשרת. מה שהדפדפן שולח בשמירה לא יכול להוסיף או להסיר תמונה, והפניות לתמונה שלא קיימת נזרקות.
- מזהה תמונה הוא תמיד באותה צורה (`a` ושמונה תווים הקסדצימליים) ונבדק מול הרשימה לפני כל קריאה או מחיקה, כך שאי אפשר להגיע דרכו לקובץ אחר.
- התמונות עוברות את אותה קליטת קבצים כמו שאר ההעלאות (סוג, גודל, קידוד מחדש), עד 2000 פיקסלים בצלע, והשם נוקה מתווי בקרה.
- גוף בקשה מוגבל ל-200,000 תווים, והטקסטים והמספרים עוברים סכמה קפדנית (מיקום בין 0 ל-1, גדלים ורכיבים מרשימה סגורה).
- הטקסטים נכנסים ל-`brief.md` בשורה אחת, כך שכותרת שנראית כמו כותרת Markdown לא משנה את מבנה המסמך. עדיין, טקסט בבריף הוא **תוכן** שהאוטומציה קוראת, לא הוראות. הסקיל אומר זאת במפורש.

## מה לא נעשה

- אין יצירת עיצוב מתוך העמוד, ואין חיבור ישיר ל-Figma או ל-Canva. Figma לא מאפשר ליצור קובצי עיצוב דרך ה-API הציבורי, ו-Canva דורש אישור נפרד לכל מארגן.
- המיקום הוא על מסגרת תצוגה בלבד, לא על העיצוב הסופי. הוא הנחיה, וה-AI או המעצב רשאים לסטות ממנו כשטקסט ארוך מדי לשורה.
- לא נבדק מול Figma ו-Canva עצמם מתוך הפרויקט הזה, רק מבנה הקבצים והקריאה שלהם.
